# macOS desktop lifecycle

The desktop helper uses the bundle identity `net.inkyquill.hieronymus` and an agent-style `LSUIElement` application. `assets/macos/Info.plist` is the bundle metadata input; the complete signed bundle, version fields, icon resources, activation and update mapping belong to packaging. Native macOS execution has **not** been qualified on this Linux development host.

## Registration and startup

`hiero desktop install|uninstall` and `hiero desktop autostart on|off|status` manage two distinct current-user LaunchAgents. Options include `--data-root`, `--unit-dir`, `--binary`, and `--json`. Defaults use `~/Library/LaunchAgents`; each filename is its label plus `.plist`. Labels are `net.inkyquill.hieronymus.{daemon|tray}.<sha256-of-canonical-root>`. The digest is an identity discriminator, not a credential. A custom agent directory is a disposable registration fixture; automatic *next login* discovery requires the normal user LaunchAgents directory or a packaging-controlled integration.

The daemon definition runs the stable installed `bin/hiero daemon --data-root ROOT`, uses `RunAtLoad=false` and `KeepAlive=false`, and is bootstrapped into `gui/<effective-uid>` without starting. Explicit Start uses `launchctl kickstart` without `-k`. The tray definition runs `bin/hiero tray` with the root, registration directory and stable CLI endpoint. It uses `RunAtLoad=true`, `KeepAlive=false`, and `LimitLoadToSessionType=Aqua`. Publishing/enabling the login preference does not bootstrap another helper immediately; launchd discovers it at the next Aqua login. The helper starts once after its trusted singleton and AppKit initialization; passive polls never start a daemon.

The deliberate recovery policy is **explicit Start/Restart after a crash**. The daemon stays stopped and eventually red after failed probes; the independent helper remains usable. There is no manager crash-retry promise on macOS. Both desktop and headless CLI lifecycle commands use the same on-demand daemon registration and authenticated controller; GUI libraries remain outside the CLI dependency graph. Native registration requires the caller's real graphical login context; an SSH/root/non-graphical session cannot select another GUI session by changing environment variables. Headless `daemon` execution itself remains available without AppKit.

Stop first disables only the daemon label, then performs the common authenticated `/shutdown` handshake, discovery disappearance and root-release checks. Start reenables that label, including an already-live daemon after a failed earlier stop. Quit exits the helper only after successful shutdown and preserves the separate tray login preference. No `launchctl kill`, hard-stop, or `kickstart -k` is used. Bootout is restricted to owned registrations whose readback has no process, after the caller's graceful daemon-stop proof. A live tray cannot be forcibly booted out by uninstall; quit it first. Coordinated live-helper removal/update remains packaging work.

The owned plist must match the complete deterministic definition. Loaded path, executable and literal argument vector are checked; a loaded keepalive policy is refused. Actual enabled state comes from `launchctl print-disabled`, so a native toggle is reflected in settings. Native human-readable output is parsed narrowly and bounded at 64 KiB; unknown formats, duplicate authority fields, missing GUI domains and unexpected recovery policies fail closed. Genuine `launchctl` output, including missing-service status 3/113, must be qualified on each supported macOS release.

## Bounded native operations and recovery

The hidden `__macos-native-broker` CLI accepts a bounded private stdin request. It acquires persistent root `.macos-native.lock` and registration-directory `.macos-native.lock` gates before READY; only an exact COMMIT permits work. Common lifecycle acquisition and registration/public-read paths check those gates before action. The parent keeps its ordinary operation guards through response or timeout. Before COMMIT, failure kills/reaps only the uncommitted broker. After COMMIT, the caller has a 30-second native-manager budget and reports timeout as **indeterminate**; it never kills launchctl, its committed broker, or the daemon. The continuing broker retains its gates through native completion, readback and rollback. A reaper waits independently of the shared worker. A stuck native call can retain one broker and its gate indefinitely; retry cannot accumulate competing brokers.

A pending journal records the prior definition, native enabled state and loaded state before publication. Normal failures restore the prior state; interrupted mutations are repaired on the next authenticated mutating call. Passive reads verify and report actual state without repairing it. Foreign state prevents rollback. A rollback failure retains its journal and is never reported as success. Definition publication uses the existing atomic, private temporary-file writer.

Browser opening uses the same private handoff with a separate persistent root `.macos-browser.lock` and a 10-second caller budget. Only the already minted local grant URL is accepted. `/usr/bin/open` receives one literal URL argument; all child streams are suppressed. URLs never appear in broker argv, returned diagnostics, logs or files. An indeterminate call may open the browser late; its held gate prevents another opener until completion. `platform::native_gate::{BROWSER_GATE, MANAGER_GATE, acquire, check}` are also the packaging ownership interfaces: update/removal must account for both kinds of committed native work before deleting executables or coordination directories. Gates are never unlinked.

## AppKit presentation and session ownership

`SessionGetInfo(callerSecuritySession)` from the public Security framework provides the current inherited SecuritySessionId and `sessionHasGraphicAccess`. Unknown IDs, query failures, root sessions and missing graphic access are rejected. Effective UID plus that session ID and the canonical data root identify the helper singleton; environment values and process-group IDs are not authority. [Apple's public AuthSession header](https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_authorization/lib/AuthSession.h) defines these fixed-width fields and inheritance.

The main-thread delegate only records launch/termination state. Tray creation waits for `applicationDidFinishLaunching` and a timer firing inside the running AppKit loop. Native menu callbacks retain bounded action bits; the controller worker owns registration, browser, settings and daemon I/O. The status button supplies its own effective appearance and window backing scale. Separate normal and highlighted RGBA images resolve foreground under that appearance, preserve the green/amber/red accent, and are explicitly non-template. A common-mode 100 ms presentation timer refreshes appearance and scale, including menu tracking; the shared daemon probe schedule remains three seconds with two-second deadlines. Unknown color resolution is an error, not a guessed automatic theme.

AppKit termination records session teardown, dismisses any owned menu, stops/wakes the loop, drops the icon and joins the worker. It never submits the user's shared-root Quit action. A pending `NSTerminateLater` is acknowledged after cleanup. Direct system termination of a LaunchAgent is still an OS lifecycle event; the adapter does not try to stop other sessions' daemon through a logout callback. LaunchAgent discovery/lifetime follows [Apple's per-user launchd model](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html).

## Native qualification

Portable Linux checks cover plist escaping, the actual daemon command, root/role identities, no automatic recovery, normal publication rollback and fail-closed readback. An Apple Silicon source-inclusion harness checks the actual native adapter/API code; it is not a complete target build, linker/ABI test, launchd execution or installed application acceptance.

On a disposable macOS graphical account/session, build the actual crates and run:

```sh
cargo test -p hiero --locked --test macos_desktop
cargo test -p hiero --locked --lib public_reads_reject_common_guard_contention_before_broker_spawn
cargo test -p hiero --locked --lib native_transport_timeout_before_commit_aborts_and_after_commit_retains_authority
cargo test -p hiero --locked --test macos_desktop native_disposable_launchagents_register_toggle_readback_and_remove -- --ignored --exact
cargo test -p hiero --locked --lib native_interrupted_registration_restores_prior_absence_and_rejects_foreign_file -- --ignored
```

The explicitly ignored registration tests create only unique temporary roots/labels and do not start a daemon or helper. The transport fixture contacts no native manager/browser; it measures private-pipe deadlines and continuing locks only. It must not be described as launchd acceptance. The real registration fixture uses a custom directory, so it does not establish next-login discovery.

Qualify a complete matching installed package on **arm64 and x86_64** separately: menu actions; grant-authenticated browser opening; actual login toggle and subsequent login; no duplicate icon; launch without Terminal; Start/Restart after a disposable daemon crash; acknowledged Quit and unchanged login preference; second graphical session teardown without a shared-root Quit; fullscreen transitions; light/dark menu bars; open-menu highlight; moving between displays with different backing scales; and readback/rollback after a failed registration. Record OS/Xcode, architecture, commit, exact package/model/runtime hashes and signing state. Use no real translation project. Native Intel runtime input remains unavailable and fails closed as documented in [desktop platform qualification](desktop-platforms.md); do not invent pins or downgrade the mandatory runtime/model.
